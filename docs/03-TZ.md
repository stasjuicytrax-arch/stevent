# ST EVENT — техническое задание на лендинг

> Читать вместе с `01-CONTENT.md` (тексты) и `02-DESIGN-SYSTEM.md` (визуал).
> Ни один текст и ни одна цифра не придумываются — всё берётся из `01-CONTENT.md`.
> Ни одно изображение не берётся из интернета — всё из `assets/`.

---

## 1. Задача

Заменить многостраничный сайт на Tilda одним лендингом. Перенести весь контент
восьми страниц кейсов, страниц «О нас» и «Контакты» на одну страницу.

**Цель страницы:** заявка на расчёт мероприятия (звонок или форма).
**Аудитория:** HR- и маркетинг-директора крупных компаний Перми и региона;
вторично — частные заказчики (свадьбы, дни рождения).

---

## 2. Стек

- Чистый **HTML + CSS + JavaScript**. Без React, без сборщиков, без npm-зависимостей в рантайме.
- Анимации — **GSAP + ScrollTrigger** (файлы кладутся в `assets/vendor/`, не с CDN).
- Один `index.html`, `css/` и `js/` разбиты на файлы по секциям.
- Сайт должен открываться двойным кликом по `index.html` без сервера.
- **JS подключается классическими `<script defer>`, без `type="module"`.**
  ES-модули браузер блокирует по протоколу `file://` (CORS), и страница
  просто не запускается. Изоляция кода — через IIFE или объект-неймспейс,
  не через `import`/`export`.

## 4. Структура лендинга

Каждая секция начинается с маркера `NN — НАЗВАНИЕ` (см. дизайн-систему, п.6).

### 00 — Прелоадер
Чёрный экран, по центру логотип `assets/brand/logo-st-white.png`, под ним
счётчик 0→100. Уход — шторка вверх, 600ms. Показывать один раз за сессию
(`sessionStorage`).

### Шапка (fixed)
Слева логотип. Справа: `О НАС` · `УСЛУГИ` · `ПОРТФОЛИО` · `КОНТАКТЫ` + кнопка
`ОБСУДИТЬ ПРОЕКТ`. При скролле вниз — скрывается, при скролле вверх —
появляется с фоном `rgba(8,8,10,.8)` + `backdrop-filter: blur(20px)`.
Мобильный — бургер на весь экран.

### 01 — Hero
Приём референса B: скруглённый «остров» (`--r-l`), отступ от краёв 24–32px,
внутри фото `assets/common/hero-main.jpg` под градиентной заливкой `--grad-hot`
в режиме наложения.

- `ST EVENT` — `display-xl`
- Дескриптор: `событие // искусство // видео` — `label`, с разрядкой
- Подзаголовок: `Организуем эффективные события с 2008 года. Пермь.`
- Кнопка primary `ОБСУДИТЬ ПРОЕКТ`
- Внизу острова индексная строка на 4 колонки:
  `#01 СОБЫТИЯ` · `#02 БТЛ` · `#03 ДИЗАЙН` · `#04 ТЕХНИЧЕСКОЕ ОБЕСПЕЧЕНИЕ`

### 02 — Манифест
Асимметричный блок референса B, три уровня текста в одном блоке.

**Слева, крупно (`display-l`):** только первая часть сообщения —
«Мы организуем эффективные события». Четыре слова, две строки максимум.

**Под ним, обычным текстом (`body-l`, ширина не более 60 символов):**
продолжение дословно — «…которые нацелены на решение бизнес-задач наших
клиентов и 100% уложимся в ваш бюджет. Сплотим команду и направим на
достижение целей.»

**Справа:** три счётчика в столбик — `18 лет опыта`, `96% постоянных
клиентов`, `2000+ гостей на крупнейшем проекте`. Докручиваются при появлении.

> **Правило для всего сайта.** `display-xl` и `display-l` — только для
> фраз до 7 слов. Любой текст длиннее набирается `body-l` или `body`.
> Абзац, набранный крупным кеглем, ломает ритм и занимает несколько
> экранов — это прямое нарушение дизайн-системы, раздел 3.

### 03 — Услуги
Четыре направления из `01-CONTENT.md` §2. Раскрывающиеся строки-аккордеон
во всю ширину: закрытая строка — номер, название, тонкая линия; раскрытая —
список подпунктов справа. Открыта всегда ровно одна. Это современнее сетки
карточек и лучше работает на мобильном.

### 04 — Почему мы  ← ЕДИНСТВЕННАЯ СВЕТЛАЯ СЕКЦИЯ
Инверсия темы по диагонали (приём референса A). Фон `--bg-light`, текст
`--text-light`. Три пункта из `01-CONTENT.md` §3 в ряд: крупная цифра
акцентом, заголовок, текст. Вход и выход секции — срезанные углы, не прямые.

### 05 — Портфолио
Главная секция. Восемь кейсов из `01-CONTENT.md` §4.

**Desktop:** секция пиннится, кейсы едут горизонтально при вертикальном
скролле. Карточка 4:5, Ч/Б, на ховер — цвет.
**Mobile:** вертикальная лента, по одной карточке.

Порядок (от сильного к слабому): `Битва роботов` → `Крон` → `Импортсервис` →
`Юникорн` → `Выпускной` → `Ibiza` → `Хогвартс` → `Свадьба`.

**Клик по карточке → полноэкранная модалка кейса:**
- Обложка на весь экран, поверх — название и мета
- Блоки `ЗАДАЧА` / `РЕШЕНИЕ` / `KPI` — точные тексты из `01-CONTENT.md`
- Мета-строка: `Место проведения` · `Количество гостей`
- Галерея всех фото кейса: сетка 3 колонки, клик → лайтбокс со стрелками,
  Esc и свайп на мобильном
- Фото подгружаются лениво: первые 6 сразу, остальные при скролле
  (в Хогвартсе 49 фото — без этого модалка будет тормозить)
- Закрытие: крестик, Esc, клик по фону. Скролл страницы блокируется.

### 06 — Клиенты
Заголовок `НАМ ДОВЕРЯЮТ` слева, справа — бесконечная лента 14 логотипов из
`assets/clients/`, монохром `opacity: .45`, ховер → `1`, пауза на ховер.

### 07 — География
**Карты нет.** `assets/common/map-geography.png` оказался спутниковым
снимком квартала с водяным знаком Google — на коммерческом сайте это
нарушение лицензии, файл не используем.

Секция строится типографикой: маркер `07 — ГЕОГРАФИЯ МЕРОПРИЯТИЙ`,
крупно названия городов в `display-m`, разделённые тонкой линией
`--line`. Сейчас известны **Пермь** и **Сочи**. Пульсация точек
запрещена — см. дизайн-систему, раздел 8.

Реальную карту добавим, когда клиент пришлёт полный список городов
(`01-CONTENT.md` §8, пункт 6).

### 08 — Контакт
Два столбца.
**Слева** — контакты из `01-CONTENT.md` §7: телефоны (кликабельные `tel:`),
email (`mailto:`), адрес, Telegram, ВКонтакте. Подписи блоков —
`МЫ ВСЕГДА НА СВЯЗИ` и `ДЛЯ НОВЫХ КЛИЕНТОВ`.
**Справа** — форма: `Ваше имя`, `Ваш телефон` (маска `+7 (___) ___-__-__`),
`Ваш email` (опционально), `О чём мероприятие` (textarea, опционально),
чекбокс согласия на обработку персональных данных со ссылкой на политику,
кнопка `Отправить`.

Валидация на клиенте, состояния: покой / отправка / успех / ошибка.
Отправку подключим позже — пока `console.log` + экран успеха.

### 09 — Футер
Логотип, дескриптор, навигация, контакты, соцсети, `© 2026 ST EVENT`,
ссылка на политику конфиденциальности. Фон — `assets/common/footer-bg.jpg`
затемнённый до 12% яркости.

## 5. Обязательные требования

1. **Все ассеты локальные.** В финальном коде не должно быть ни одной ссылки
   на `tildacdn.com` или любой внешний CDN. Проверяется поиском по проекту.
2. **Все тексты — из `01-CONTENT.md`.** Ничего не переписывать «красиво»,
   ничего не добавлять. Исправить только опечатки, отмеченные `→`.
3. **Все цифры — из `01-CONTENT.md`.** Ни одной выдуманной метрики.
4. Раздела «Отзывы», «Цены» и блока «Команда» **в первой версии нет** —
   контента для них не существует (см. `01-CONTENT.md` §8).
5. Работоспособность: Chrome, Safari, Firefox, Edge — последние две версии.
6. Мобильный — от 360px.
7. Метрики: LCP < 2.0s, CLS < 0.05, Lighthouse Performance ≥ 90.
8. Доступность: фокус виден у всех интерактивных элементов, модалка ловит
   фокус, Esc закрывает, `prefers-reduced-motion` отключает анимации.
9. SEO: `<title>`, `<meta description>`, Open Graph, `favicon`, `robots.txt`,
   `sitemap.xml`, JSON-LD `LocalBusiness` с адресом и телефоном.
10. Редиректы со старых URL — список в `01-CONTENT.md` §9.

## 6. Порядок сборки

Собирать по шагам, каждый шаг — отдельный промт в терминале. Не пытаться
сгенерировать весь сайт одной командой.

1. Структура папок + `tokens.css` + `reset.css` + `base.css`
2. Шапка + прелоадер
3. Hero (01) + манифест (02)
4. Услуги (03) + почему мы (04)
5. Портфолио (05) — сетка карточек, без модалки
6. Модалка кейса + галерея + лайтбокс
7. Клиенты (06) + география (07)
8. Контакты (08) + форма + футер (09)
9. Анимации GSAP по всем секциям
10. Адаптив: планшет, мобильный
11. Оптимизация: webp, lazy, шрифты, метрики
12. Финальный прогон антислоп-чеклиста из `02-DESIGN-SYSTEM.md` §9
