## R22. Hero — текст всё ещё не по центру, только по горизонтали — КРИТИЧНО

Прошлый фикс (R18) добавил `text-align`/`align-items`, но контент острова
визуально прижат к верху. Проверить фактическую структуру: скорее всего
у `.hero__content` нет `height: 100%` или `justify-content: center` по
вертикали внутри острова, либо родительский контейнер не flex. Сделать
hero-контент flex-колонкой с `justify-content: center; align-items: center`
на всю высоту острова, замерить `getBoundingClientRect()` — вертикальный
центр блока контента должен совпадать с вертикальным центром острова
±8px.

## R23. Аккордеон услуг — реальный баг, не мнимый — КРИТИЧНО

Раскрывается только карточка №3 «Дизайн». «БТЛ», «Техническое
обеспечение» и остальные не реагируют на клик вообще. Прошлая проверка
(R19) была неполной. Нужно построчно пройти JS: убедиться, что цикл
создания слушателей вешает click на каждый `.accordion__item` по
отдельности (частая причина — замыкание на индексе в цикле через `var`
вместо `let`, или селектор жёстко захардкожен на один элемент вместо
`querySelectorAll`). Доказательство — не «работает на глаз», а клик по
каждой из 4 карточек по очереди со скриншотом раскрытого состояния
каждой.

## R24. Переход чёрный → белый → чёрный между «Почему мы» и «Портфолио»

Слишком резкий. Портфолио остаётся тёмным (правило «единственная
светлая секция» не трогаем). Сделать плавный переход фона по скроллу —
по образцу R16 пункт 4 («Смена темы по скроллу», scrub-интерполяция
background и цвета текста), только в обратную сторону — на выходе из
светлой секции в тёмную. Никакой жёсткой границы между секциями.

## R25. Метки на карте — редизайн + осознанное исключение из правила

Клиент явно решил: метки Перми/Сочи/Москвы/Петербурга/Новосибирска/
Екатеринбурга должны быть интерактивными кружочками с мягким миганием
(pulse). Это осознанное исключение из общего запрета на pulse в
`02-DESIGN-SYSTEM.md` §8 и `05-REVISION-02.md` R16 — общий запрет
остаётся в силе для всех остальных элементов сайта, но здесь письменно
фиксируется, что для меток географии сделано исключение по прямому
решению клиента, чтобы дизайн-система не противоречила сама себе.
Мигание — мягкое и медленное (не чаще раза в 2–3 секунды, `opacity` или
`scale` в узком диапазоне), не «лампочка на ёлке».

**Отдельный баг:** метка «Москва» дёргается вверх-вниз при движении
мыши по карте. Не относится к общему наклону карты (R20) — похоже на
логику разведения соседних подписей (Москва/Питер физически близко),
которая пересчитывается на каждое движение мыши вместе с наклоном.
Разведение подписей должно считаться один раз при построении карты
(или при resize), а не на каждый mousemove/tilt-тик — иначе она
«плавает».

## R26. Сайту не хватает плотности — ощущение недоделанности

Пройтись повторно по R12 (тонкие линии как сквозной приём — над каждым
маркером секции, между колонками, прочерчивание при появлении) и
проверить, что оно применено во всех секциях, не только в hero. Также
проверить, какие пункты R16 (11 приёмов движения) ещё не реализованы
полностью, и добить оставшиеся — это основной источник ощущения
«статичного макета».
